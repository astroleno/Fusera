# Prompt Reuse Discipline

## Goal

Use prompt references as a design pattern library, not as direct requirements.

## Extract

- Section order and layout rhythm.
- Material language, typography hierarchy, and color relationships.
- Motion recipes and triggers.
- Asset handling patterns.
- Component ideas that fit the current brief.

## Do Not Copy

- Prompt-origin brand names, claims, testimonials, customer logos, or metrics.
- Prompt-origin external media URLs unless approved.
- Unrelated dependencies such as backend servers, AI SDKs, analytics, or CDNs.
- Full HTML/JS code blocks that conflict with the target stack.
- Multiple prompts' complete requirements merged into one overloaded page.

## Conflict Resolution

1. User brief and existing project constraints.
2. Fusera artifacts and schema contracts.
3. Route Card selected primary pattern.
4. Supporting pattern details.
5. Raw prompt text.

## Required Handoff

- List selected prompt IDs.
- List patterns reused.
- List patterns intentionally ignored.
- List asset risks and fallbacks.
